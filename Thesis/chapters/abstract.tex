\section*{Abstract}\label{chapter:abstract}
\thispagestyle{fancy}
\begingroup
\setlength{\parindent}{0pt}
\setlength{\parskip}{0.45em}

Robot Operating System 2 (ROS~2) is a middleware that is widely used to build
robotic applications. A ROS~2 application often contains many nodes that
communicate through topics, services, and actions. This makes the application
flexible, but it can also make its runtime behaviour difficult to understand,
so the running system has to be monitored. Existing monitoring solutions often
focus on one communication type, one monitoring method, or one deployment
setup. Developers therefore need to write extra monitoring code for each new
application.

In this thesis, we present a configurable monitoring infrastructure for ROS~2
applications. We built it as a reusable foundation for collecting, processing,
routing, checking, and exporting runtime data from heterogeneous ROS~2
interfaces. The infrastructure observes topics, service events, and action
feedback and status, and converts these different observations into a common
data format. Each data record includes the observed data and useful context,
such as its source, time, session, and identifier.

Users describe the monitoring setup in YAML files. They can
select data sources, reduce or filter data, choose outputs, and connect
property-specific checking components. New data converters, verdict services,
input sources, and output exporters can also be added as separately developed
components without changing the monitoring core. The deployment
configurations are generated automatically from the user's selections.

The infrastructure runs in two ways. In the integrated setup, data collection
and checking run together. In the split setup, data is collected near the robot
and sent to a separate verifier that can run on a different machine. The
concrete prototype supports file and MQTT transport and provides processing
steps such as field selection, rate limiting, and change filtering.

We evaluated the prototype through case studies covering topic, service, and
action monitoring, including a Navigation~2 case study, complemented by unit
tests, Docker Compose deployments, offline replay, a multi-robot scenario, and
a three-machine deployment on Ubuntu, Raspberry Pi, and macOS.
Across these scenarios, the same data format and processing chain connected
ROS~2 topics, service events, and action progress to reusable checking
components in both integrated and split deployments. In the three-machine
experiment, both verifier processes received all 4173 data records, and all
34 verdict transitions on the macOS verifier matched the Pi reference exactly.
