\section{Config Generator}

The generator creates ROS2-Monitor-Infra runtime YAML from a JSON generation
request. The request is written as a deployment model: physical
\texttt{hosts} contain executable \texttt{runtimes}, and \texttt{links}
describe how hosts exchange records, DSL records, or verdicts.

\begin{enumerate}
  \item discover visible ROS2 topics, services, and actions;
  \item place runtimes on physical hosts;
  \item select monitor, converter, and verdict service classes;
  \item describe host links and transport kinds;
  \item project the JSON request into one or more runtime YAML files.
\end{enumerate}

\section{Generation Request JSON}

The JSON request has two top-level sections:

\begin{tabular}{@{}p{0.20\linewidth}p{0.73\linewidth}@{}}
\toprule
Section & Meaning \\
\midrule
\texttt{hosts} &
Physical devices. Each host owns the runtimes that execute on that device. \\
\texttt{links} &
Connections between hosts. Each link names its \texttt{from\_host},
\texttt{to\_host}, endpoint runtimes, payload, and transport. \\
\bottomrule
\end{tabular}

\subsection{Runtime Kinds}

Every runtime belongs to exactly one host and uses a \texttt{kind} field to
select its shape.

\begin{tabular}{@{}p{0.20\linewidth}p{0.73\linewidth}@{}}
\toprule
\texttt{kind} & Meaning \\
\midrule
\texttt{ros2} &
The ROS2 graph visible on the host. Its \texttt{sources} are the monitorable
resources. \texttt{Source.source\_kind} is an enumeration:
\texttt{topic}, \texttt{service}, or \texttt{action}. \\
\texttt{monitor} &
Subscribes to selected ROS2 sources; outgoing DataRecords are routed by links. \\
\texttt{converter} &
Reads records from \texttt{input\_from} and writes DSL records to \texttt{output\_to}. A converter may be a
\texttt{data\_filter} or a \texttt{dsl\_converter}; both are custom class-path
based converter runtimes. \\
\texttt{verdict\_service} &
Reads DSL records or verdict records from \texttt{input\_from} and sends verdicts to \texttt{output\_to}. \\
\bottomrule
\end{tabular}

\vspace{0.5em}

\texttt{Transport} is not a standalone top-level section in the request. It is
the implementation object inside a \texttt{Link}. Existing transport kinds are
\texttt{file} and \texttt{mqtt}.

\section{Config Generation Algorithm}

\begin{algorithm}[H]
\caption{Generate runtime YAML from JSON}
\begin{algorithmic}[1]
\Require generation request $J$
\Ensure generated YAML files $F$
\State $F \gets \emptyset$
\State $Runtimes \gets \Call{IndexRuntimes}{J.\text{hosts}}$
\ForAll{host $H$ in $J.\text{hosts}$}
  \ForAll{runtime $R$ in $H.\text{runtimes}$}
    \If{$R.\text{kind}=\text{ros2}$}
      \State add $R.\text{sources}$ to the source catalogue
    \ElsIf{$R.\text{kind}=\text{monitor}$}
      \State $Y \gets \Call{NewYAML}{H,R}$
      \ForAll{source id $s$ in $R.\text{subscribe}$}
        \State add $\Call{MakeMonitoredSourceEntry}{s,J}$ to $Y$
      \EndFor
      \ForAll{outgoing link $e$ from $R$ where $e.\text{payload}=\text{records}$}
        \State $records \gets \Call{ResolveLinkRecords}{e,J}$
        \State $\Call{AttachDataRecordExporter}{Y,e.\text{transport},records}$
      \EndFor
      \State $F[\Call{YamlFile}{H,R}] \gets Y$
    \ElsIf{$R.\text{kind}=\text{converter}$}
      \State $Y \gets \Call{NewYAML}{H,R}$
      \State $chain \gets \Call{MakeConverterEntry}{R}$
      \State $chain.\text{input\_from} \gets \Call{ResolveInputs}{R.\text{input\_from},J}$
      \ForAll{incoming link $e$ to $R$}
        \State $Y.\text{verdict\_runner.source} \gets \Call{MakeRunnerSource}{e.\text{transport},e.\text{payload}}$
      \EndFor
      \ForAll{outgoing link $e$ from $R$ where $e.\text{payload}=\text{dsl}$}
        \State $chain.\text{dsl\_transport} \gets e.\text{transport}$
      \EndFor
      \State add $chain$ to $Y.\text{converters}$
      \State $F[\Call{YamlFile}{H,R}] \gets Y$
    \ElsIf{$R.\text{kind}=\text{verdict\_service}$}
      \State $Y \gets \Call{NewYAML}{H,R}$
      \ForAll{incoming link $e$ to $R$}
        \State $Y.\text{verdict\_runner.source} \gets \Call{MakeRunnerSource}{e.\text{transport},e.\text{payload}}$
      \EndFor
      \State add $\Call{MakeVerdictEntry}{R}$ to $Y.\text{converters}$
      \State $F[\Call{YamlFile}{H,R}] \gets Y$
    \EndIf
  \EndFor
\EndFor
\State \Call{WriteYAMLFiles}{F}
\State \Return $F$
\end{algorithmic}
\end{algorithm}

\section{Runtime Resource Scanning}

\begin{algorithm}[H]
\caption{Scan ROS2 sources}
\begin{algorithmic}[1]
\Ensure source catalogue $G$
\State $T \gets$ run \texttt{ros2 topic list -t}
\State $V \gets$ run \texttt{ros2 service list -t}
\State $A \gets$ run \texttt{ros2 action list -t}
\State $G \gets \emptyset$
\ForAll{topic $(name,interface)$ in $T$}
  \State add source $(topic,name,interface)$ to $G$
\EndFor
\ForAll{service $(name,interface)$ in $V$}
  \State add source $(service,name,interface)$ to $G$
\EndFor
\ForAll{action $(name,interface)$ in $A$}
  \State add source $(action,name,interface)$ to $G$
\EndFor
\State \Return sorted $G$
\end{algorithmic}
\end{algorithm}

\section{Projection Rules}

\subsection{Host and Runtime}

Each \texttt{Host} becomes a placement boundary. The generator does not emit a
YAML file for the host itself; it derives one YAML file for each executable
runtime.

\begin{itemize}
  \item \texttt{ROS2} runtimes provide \texttt{Source} definitions.
  \item \texttt{Monitor} runtimes capture sources and emit DataRecords.
  \item \texttt{Converter} runtimes build converter entries. \texttt{data\_filter}
        and \texttt{dsl\_converter} use the same class-path mechanism.
  \item \texttt{VerdictService} runtimes build verdict entries and output targets.
\end{itemize}

\subsection{Source}

Sources live under a \texttt{ROS2} runtime. A source is selected by id and then
projected to the generated monitor YAML according to its
\texttt{source\_kind}:

\begin{itemize}
  \item \texttt{topic} sources become entries under \texttt{topics};
  \item \texttt{service} sources become entries under \texttt{services};
  \item \texttt{action} sources become entries under \texttt{actions}.
\end{itemize}

\subsection{Link and Transport}

A \texttt{Link} connects two hosts. Its \texttt{from\_runtime} and
\texttt{to\_runtime} fields name the endpoint runtimes. Its
\texttt{transport} block is copied to the generated runtime YAML according to
\texttt{payload}:

\begin{itemize}
  \item \texttt{records}: the source side becomes a DataRecord exporter and the
        target side becomes a \texttt{verdict\_runner.source}.
  \item \texttt{dsl}: the converter side becomes \texttt{dsl\_transport}; the
        verdict side uses the same transport.
  \item \texttt{verdicts}: the source side becomes a verdict exporter and the
        target side becomes a \texttt{verdict\_runner.source}.
\end{itemize}

The link does not repeat record ids. The generator derives the transported
record set from the source runtime's \texttt{subscribe} or \texttt{output\_to}
field and the target runtime's \texttt{input\_from}.
